# Proposal: v0.2 产品重建 — 从原型到真正的产品

## 一、产品经理视角：根本问题不是功能缺失

v0.1 的问题不是"功能不够多"，而是**产品根本不存在**。你有一个技术原型，但没有产品。

### 1.1 产品定位：你到底是谁？

**一句话说不清楚的产品，不是产品。**

| 可能的定位 | 问题 |
|-----------|------|
| "企业知识管理平台" | 太泛。飞书、语雀、Confluence 都这么说。你的差异化在哪？ |
| "基于 AI 的知识库" | Notion AI、飞书智能伙伴都做了。你的 AI 比它们强在哪？ |
| "私有部署的知识管理" | Confluence Data Center 支持私有部署。为什么选你？ |
| "制造业知识管理" | 这个定位有戏，但你的产品没有任何制造业特征。 |

**核心问题：你没有选择战场。** 你试图做一个"通用的企业知识管理平台"，但这个市场已经被巨头瓜分完毕。你唯一的生存空间是**垂直领域**——针对特定行业、特定场景的深度解决方案。

### 1.2 目标用户：你到底给谁用？

v0.1 假设"企业员工"是用户。但"企业员工"不是一个人，是几百个完全不同的人：

| 用户角色 | 核心需求 | v0.1 满足了吗？ |
|---------|---------|----------------|
| 一线工程师 | 快速找到故障解决方案，不写文档 | ❌ 需要他写文档才能用 |
| 知识管理员 | 整理、分类、审核知识 | ⚠️ 有 API 没界面 |
| 部门经理 | 了解团队知识资产，发现知识缺口 | ❌ 完全没有 |
| IT 管理员 | 部署、运维、监控 | ⚠️ 有 systemd 但缺监控 |
| 新员工 | 快速学习，找到 SOP | ❌ 没有学习路径 |
| 高层管理者 | 知识资产可视化、ROI | ❌ 完全没有 |

**核心问题：你为"所有人"设计，结果对"没有人"好用。**

### 1.3 用户价值主张：为什么不用飞书？

一个博世工程师现在的工作流：
1. 在 Word 里写故障分析报告
2. 邮件发给经理审批
3. 经理转发给相关团队
4. 有人把它存到 SharePoint
5. 三个月后没人记得它在哪
6. 新员工遇到同样问题，从头再来

你的产品要替代这个流程。但你的价值主张是什么？

| 价值主张 | 是否成立 |
|---------|---------|
| "自动同步，不用手动上传" | ⚠️ 飞书文档自动保存到云端，比你还方便 |
| "AI 自动分类" | ⚠️ 分类准确率未知，分类错了比不分类更糟 |
| "企业知识库全员共享" | ⚠️ SharePoint 已经做到了 |
| "AI 问答" | ⚠️ 飞书智能伙伴也能做 |

**核心问题：你没有不可替代的价值。** 用户迁移成本很高（改变工作习惯、IT 部署、数据迁移），但获得的价值不明确。

### 1.4 产品冷启动：空知识库是死知识库

这是最致命的问题。企业知识库的价值 = 内容数量 × 内容质量 × 可发现性。

v0.1 部署后，企业知识库是空的。管理员需要：
1. 说服员工安装桌面应用
2. 说服员工把文档放到同步目录
3. 等待足够多的文档积累
4. 手动审核分类
5. 才能看到价值

**这个过程中，任何一个环节断了，产品就死了。** 员工为什么要装？装了为什么要放文档？放了文档为什么要等？

### 1.5 竞品分析：你不是在真空里竞争

| 竞品 | 优势 | 你的机会 |
|------|------|---------|
| **飞书** | 一站式协作，文档+IM+会议 | 私有部署、数据不出域 |
| **语雀** | 知识库体验好，结构化 | 私有部署、AI 能力 |
| **Confluence** | 企业市场霸主，Jira 集成 | 轻量、便宜、AI 原生 |
| **Notion** | 灵活、好用、AI | 私有部署、制造业场景 |
| **SharePoint** | 微软生态，企业标配 | 体验好、AI 搜索 |
| **GitBook** | 技术文档 | 非技术场景 |

**你的唯一差异化空间：私有部署 + 制造业垂直场景 + AI 原生。**

### 1.6 商业模式：这个产品怎么活下去？

v0.1 完全没有考虑商业模式。开源免费？企业订阅？咨询实施？

| 模式 | 可行性 |
|------|--------|
| 开源免费 + 企业版付费 | ✅ 常见模式，但需要明确企业版多什么 |
| SaaS 订阅 | ❌ 博世要求私有部署 |
| 私有部署 license | ✅ 按用户数/文档量收费 |
| 咨询实施 | ✅ 制造业知识管理咨询 + 产品 |

**核心问题：没有商业模式的产品是爱好，不是产品。**

## 二、产品经理视角：v0.2 应该做什么

### 2.1 重新定义产品定位

**一句话定位：面向制造业的 AI 原生知识管理平台，私有部署，数据不出域。**

为什么选制造业？
- 博世是你的第一个客户，也是最好的标杆
- 制造业有独特的知识类型：故障分析报告(FA)、工程变更通知(ECN)、工艺规范、质检标准、SOP
- 这些知识类型有固定结构，AI 可以深度理解
- 制造业对数据安全要求极高，私有部署是刚需
- 通用平台（飞书/语雀）不做制造业垂直场景

### 2.2 重新定义目标用户

**核心用户画像：制造业一线工程师**

- 每天处理故障、写分析报告
- 需要快速找到历史类似案例
- 不想花时间整理文档
- 对 IT 工具耐心有限

**次要用户：知识管理员、部门经理、IT 管理员**

### 2.3 重新定义价值主张

**对一线工程师：**
- "写完报告自动归档，不用管它"
- "遇到故障，5 秒搜到历史解决方案"
- "AI 帮你写报告初稿，你只需要修改"

**对知识管理员：**
- "AI 自动分类，你只需要审核"
- "一眼看到哪些知识缺失"
- "知识资产可视化报表"

**对部门经理：**
- "团队知识不随人员流失而丢失"
- "新人上手时间缩短 50%"
- "重复故障率下降"

**对 IT 管理员：**
- "一键部署，30 分钟上线"
- "数据完全在本地，不出域"
- "自动备份、监控告警"

### 2.4 重新定义核心场景（制造业垂直）

**场景 1：故障分析知识复用**
- 工程师遇到注塑缺陷 → 搜索"注塑 缩痕" → 找到 3 份历史 FA 报告 → AI 总结根因和措施 → 5 分钟解决问题（原来要 2 小时）

**场景 2：工程变更追溯**
- 质量审核员需要知道某个零件为什么改了 → 搜索零件号 → 看到完整 ECN 历史 → 每次变更的原因、影响、审批记录

**场景 3：新人培训加速**
- 新员工入职 → 系统根据岗位推荐学习路径 → SOP + 历史案例 + 常见问题 → 2 周上手（原来 2 个月）

**场景 4：知识资产盘点**
- 部门经理查看知识仪表盘 → 看到哪些领域文档多、哪些空白 → 发现"来料检验"只有 2 份文档 → 安排补充

### 2.5 定义"啊哈时刻"

用户打开产品后，**30 秒内**应该看到：
1. 一个搜索框（像 Google 一样简单）
2. 输入任何关键词，立即返回结果
3. 结果包含：文档标题、AI 摘要、相关度评分
4. 点击 AI 问答，得到基于知识库的回答

**这不是"功能"，这是产品存在的理由。**

### 2.6 定义商业模式

v0.2 采用 **Open Core** 模式：
- **社区版（开源免费）**：核心功能，单机部署，社区支持
- **企业版（付费）**：高可用、SSO/LDAP、审计合规、专属支持、知识分析仪表盘

定价参考：Confluence Data Center（$10/用户/月），你的定价可以 $3-5/用户/月。

### 2.7 定义产品路线图

```
v0.1 (已完成) — 技术原型，验证可行性
v0.2 (当前)   — 产品重建，制造业垂直场景，端到端可用
v0.3          — 知识分析仪表盘、SSO/LDAP、高可用
v0.4          — 多企业租户、知识图谱、智能推荐
v1.0          — 企业版正式发布，付费客户 3+
```

## 三、架构师视角：v0.2 技术方案

### 3.1 架构决策

**决策 1：放弃改造 Open Notebook，改为"嵌入 + 代理"模式**

Open Notebook 是单用户设计，改造它等于维护一个 fork。v0.2 将其作为个人知识库引擎嵌入桌面应用，不做任何代码修改。企业知识库完全自建。

**决策 2：自建企业知识库引擎**

不再使用 Open Notebook 实例作为企业知识库。自建搜索 + 存储 + AI 问答。

| 组件 | 选型 | 原因 |
|------|------|------|
| 全文搜索 | Meilisearch | 单文件部署，中文分词，< 50MB 内存 |
| 向量搜索 | Qdrant | Rust 编写，高性能，支持过滤 |
| 文档存储 | MinIO (已有) | S3 兼容，已有部署 |
| 元数据存储 | SurrealDB (已有) | 已有部署，支持图查询 |
| 任务队列 | Redis + RQ | 轻量，Python 原生 |
| AI 问答 | Ollama (已有) | 已有部署，本地推理 |

**决策 3：桌面应用重写为真正的桌面应用**

将核心逻辑从 Next.js 前端移到 Rust 后端：
- 文件系统监控（notify-rs）
- 原生通知（tauri-plugin-notification）
- 离线检测（Tauri network API）
- 一键初始化（setup.sh 集成到应用启动流程）

**决策 4：制造业知识模型**

为制造业知识类型设计专用数据模型：

```
制造业知识类型：
├── 故障分析报告 (FA Report)
│   ├── 现象、根因、措施、零件号、产线、日期
│   └── 关联：同类故障、同一零件、同一产线
├── 工程变更通知 (ECN)
│   ├── 变更原因、影响范围、审批记录、生效日期
│   └── 关联：变更前后的零件/文档
├── 工艺规范 (Process Spec)
│   ├── 工艺参数、适用产品、版本历史
│   └── 关联：相关质检标准
├── 质检标准 (Quality Standard)
│   ├── 检测方法、合格标准、抽样方案
│   └── 关联：相关工艺规范
└── 标准操作流程 (SOP)
    ├── 步骤、注意事项、所需工具
    └── 关联：相关故障案例
```

**决策 5：知识图谱**

不只是全文搜索，而是构建知识之间的关联：

```
FA-2024-001 (注塑缩痕)
  ├── 关联零件: P/N 12345
  ├── 关联产线: Line 3
  ├── 关联ECN: ECN-2024-056 (模具修改)
  ├── 类似故障: FA-2023-089, FA-2024-012
  └── 参考SOP: SOP-Injection-03
```

SurrealDB 原生支持图查询，可以直接用。

**决策 6：冷启动方案 — 不只是模板**

v0.1 的"模板"思路太浅。v0.2 需要：

1. **行业知识模型预设**：制造业分类树、标签体系、关联规则
2. **示例数据**：基于博世真实场景的 50+ 份示例文档
3. **批量导入**：从现有 SharePoint/文件服务器导入
4. **AI 辅助录入**：上传文档 → AI 自动提取结构化字段
5. **快速开始向导**：5 步引导，5 分钟看到价值

### 3.2 新增服务

| 服务 | 端口 | 用途 |
|------|------|------|
| `enterprise-km-search` | 5059 | Meilisearch + Qdrant + RAG 问答 |
| `enterprise-km-worker` | — | RQ 任务队列（解析/向量化/分类/发布） |
| `enterprise-km-analytics` | 5060 | 知识分析（热门文档、知识缺口、使用统计） |
| Redis | 6379 | 任务队列 + 缓存 |

### 3.3 移除服务

| 服务 | 原因 |
|------|------|
| 企业 Open Notebook 实例 (:5058) | 单用户设计，无法权限过滤，被自建搜索服务替代 |

### 3.4 核心链路（端到端自动化）

```
文件保存 → notify检测(5s) → rclone同步 → MinIO webhook
→ Worker下载 → 解析 → 制造业字段提取 → 向量化(bge-m3)
→ 分类(Ollama) → 知识图谱关联 → 审核队列
→ 管理员通过 → 发布到Meilisearch+Qdrant → 全员可搜索
```

### 3.5 数据安全架构

博世级别要求：
- 传输加密：HTTPS/TLS 1.3
- 存储加密：MinIO 服务端加密
- 认证：JWT + bcrypt
- 审计日志：所有操作记录（谁、何时、做了什么、结果）
- 数据隔离：多租户数据物理隔离（MinIO bucket 级别）
- 备份：每日自动备份 SurrealDB + MinIO
- 合规：支持数据导出、数据删除（GDPR 准备）

### 3.6 扩展性设计

| 规模 | 用户数 | 文档数 | 架构 |
|------|--------|--------|------|
| 小型 | < 100 | < 1万 | 单机部署，全部服务在一台机器 |
| 中型 | 100-1000 | 1-10万 | Meilisearch 集群，Qdrant 集群，Worker 多实例 |
| 大型 | 1000+ | 10万+ | 微服务拆分，K8s 部署，CDN 加速 |

v0.2 先做小型，架构预留扩展点。

## 七、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 制造业知识模型设计错误 | 高 | 与博世专家深度访谈，迭代 3 版 |
| AI 分类准确率不足 | 高 | 人工审核门禁，置信度阈值，持续训练 |
| 用户不改变工作习惯 | 高 | 文件自动同步，零额外操作 |
| Open Notebook 上游不兼容 | 中 | 锁定版本，CI 自动检测 |
| 竞品快速跟进 | 中 | 制造业垂直深度是护城河 |
| 团队规模不足 | 中 | 聚焦 P0，砍掉一切非核心功能 |
